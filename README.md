# SkyShift RAG - בוט שאלות ותשובות

בוט שעונה על שאלות על SkyShift (עולים לאוויר) רק מתוך מאגר הידע שבתיקייה `skyshift_kb`. מאגר הידע כתוב בעברית.

## איך זה עובד

1. **טעינה (פעם אחת):** `ingest.py` מחלק את המסמכים לפי כותרות `##`, ואז ל-512 טוקנים עם חפיפה של 64, יוצר וקטורים עם Gemini Embedding ושומר ב-ChromaDB.
2. **שאלה:** שאלה בעברית שעומדת בפני עצמה עוברת ישר לחיפוש, בלי קריאה ל-Gemini. אם השאלה לא בעברית (למשל באנגלית), או שהיא שאלת המשך, Gemini מתרגם ומשכתב אותה לשאילתה בעברית.
3. **חיפוש:** חיפוש וקטורי שמחזיר את 4 הקטעים הקרובים ביותר לשאלה.
4. **תשובה:** Gemini עונה מתוך 4 הקטעים בלבד, בשפת השאלה, בלי להציג מקורות למשתמש.

**רכיבים אופציונליים (כבויים כרגע, ב-`config.py`):**
- **BM25:** חיפוש מילות מפתח שמתמזג עם החיפוש הווקטורי ב-RRF. ב-BM25 מוסרות אותיות שימוש בתחילת מילה (ו, ה, ב, כ, ל, מ, ש), כדי ש"ההגרלה" ו"בהגרלה" ייחשבו לאותה מילה. כבוי לפי תוצאות הבדיקה (ראו "בעיות ודרכי פתרון").
- **Reranker:** מודל מקומי שמדרג מחדש את המועמדים ובוחר את 4 הטובים ביותר. כבוי, כי ההורדה שלו נחסמה בסינון האינטרנט.

## הקבצים

| קובץ | תפקיד |
|---|---|
| `config.py` | כל ההגדרות: מודלים, גודל קטעים, Top-K, מתגים, הכללים של הבוט |
| `check_models.py` | בדיקה שהמודלים זמינים במפתח שלכם |
| `ingest.py` | טעינת המסמכים ל-ChromaDB |
| `rag.py` | הלוגיקה: שכתוב, חיפוש, Rerank, תשובה |
| `chat_app.py` | ממשק Streamlit |
| `evaluate.py` + `eval_questions.json` | בדיקה: האם Hybrid ו-Reranker משפרים את החיפוש |

## התקנה (פעם אחת)

הרצה על סביבה וירטואלית נפרדת, בתוך התיקייה `skyshift_bot`:

```powershell
cd skyshift_bot
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

מפתח Gemini (אם לא שמרתם אותו עם `setx`):

```powershell
$env:GOOGLE_API_KEY="YOUR_API_KEY"
```

## הרצה, לפי הסדר

```powershell
python check_models.py         # 1. בדיקת המודלים
python ingest.py               # 2. טעינת המסמכים (שוב רק אם המסמכים השתנו)
python evaluate.py             # 3. בדיקת איכות החיפוש
streamlit run chat_app.py      # 4. הצ'אט
```

אם מפעילים את ה-Reranker (`USE_RERANKER = True`), בהרצה הראשונה הוא יורד מ-Hugging Face (כ-0.5GB), פעם אחת בלבד.

## מודלים ומעבר אוטומטי

ב-`config.py` מוגדרת רשימה `CHAT_MODELS`, לפי סדר עדיפות. אם מודל עמוס (503) או שנגמרה המכסה שלו (429), הבוט עובר מיד למודל הבא. בסרגל הצד מוצגת הרשימה, ובאזור "שלבי חיפוש" מוצג איזה מודל ענה בפועל.

## הצגת מקורות

`SHOW_SOURCES = False` ב-`config.py`: המשתמש לא רואה מקורות, והסימונים `[Source N]` מוסרים מהתשובה. כדי להציג מקורות (רק אלה שהתשובה ציטטה), משנים ל-`True`.

## מתגים ללמידה

ב-`config.py`, או בסרגל הצד של הצ'אט:

- `USE_BM25`: חיפוש מילות מפתח ומיזוג RRF.
- `USE_RERANKER`: דירוג מחדש.
- `USE_QUERY_REWRITE`: תרגום ושכתוב שאלות.

אם מכבים את שלושתם, מקבלים RAG וקטורי בסיסי.

## סף רלוונטיות

`MIN_RERANK_SCORE` כבוי (`None`). מריצים קודם את `evaluate.py`, ובודקים בסוף הפלט את הציון הנמוך ביותר של שאלה רלוונטית מול הציון הגבוה ביותר של שאלה לא רלוונטית. קובעים סף רק אם יש פער ברור ביניהם.

## שגיאות נפוצות

- `Missing GOOGLE_API_KEY`: המפתח לא מוגדר בטרמינל הזה.
- `429` / `RESOURCE_EXHAUSTED`: עברתם את מכסת הבקשות החינמית לדקה (למשל 100 בקשות Embedding בדקה). `ingest.py` כבר טוען במנות של 90 עם המתנה של דקה ביניהן. אם השגיאה מופיעה בצ'אט או בבדיקה, חכו דקה ונסו שוב.
- `The knowledge base is empty`: צריך להריץ קודם את `python ingest.py`.

## 🧩 בעיות ודרכי פתרון שנתקלתי בהן במהלך הפיתוח

### 1. חריגה ממכסת ה-Embedding במסלול החינמי

**הבעיה:** בטעינה הראשונה של המאגר, `ingest.py` קרס אחרי 100 קטעים עם השגיאה `429 RESOURCE_EXHAUSTED`. המסלול החינמי של Gemini מאפשר עד 100 בקשות Embedding בדקה, וכל קטע נספר כבקשה נפרדת.

**הפתרון:** שיניתי את הטעינה כך שתתבצע במנות. בכל פעם נשלחים 90 קטעים, קצת מתחת למגבלה כדי להשאיר מרווח ביטחון, ואחריהם הקוד ממתין 60 שניות לפני המנה הבאה. גודל המנה מוגדר ב-`config.py` (`EMBED_REQUESTS_PER_MINUTE`), כך שאם המגבלה תשתנה מספיק לעדכן מספר אחד. הטעינה לוקחת עכשיו כמה דקות, אבל היא מסתיימת תמיד בהצלחה ונשארת בחינם.

### 2. עומס על מודל התשובות

**הבעיה:** הצ'אט "חיפש" יותר משתי דקות בלי לענות. בלוג גיליתי את השגיאה `503 UNAVAILABLE`: המודל `gemini-3.8-flash` היה עמוס אצל גוגל, והקוד המשיך לנסות שוב ושוב את אותו מודל.

**הפתרון:** במקום מודל אחד, הגדרתי ב-`config.py` רשימת מודלים לפי סדר עדיפות (`CHAT_MODELS`). כל מודל מנסה פעם אחת בלבד. אם הוא מחזיר עומס (503) או חריגה ממכסה (429), הבוט עובר מיד למודל הבא ברשימה. שגיאה מסוג אחר, כמו מפתח שגוי, לא גורמת למעבר, כי מודל אחר לא יפתור אותה. באזור "שלבי חיפוש" מוצג איזה מודל ענה בפועל, כך שאפשר לראות מתי התרחש מעבר.

### 3. חיפוש מילות מפתח בעברית, והחלטה לפי מדידה

**הבעיה:** אחרי שהעברתי את מאגר הידע לעברית, חיפוש מילות המפתח (BM25) התקשה. בעברית אותיות השימוש נצמדות למילה, ולכן "הגרלה", "ההגרלה" ו"בהגרלה" נחשבו בעיניו לשלוש מילים שונות, ושאלה לא מצאה קטע שבו המילה כתובה בצורה אחרת.

**הפתרון:** כתבתי מנגנון פשוט (`HebrewPrefixStemmer` ב-`rag.py`) שמסיר עד שתי אותיות שימוש (ו, ה, ב, כ, ל, מ, ש) מתחילת כל מילה, גם במסמכים וגם בשאלה, כך שכל הצורות מתאימות זו לזו.

**המדידה:** במקום להניח שחיפוש משולב (Hybrid) עדיף, בדקתי את זה עם `evaluate.py`, סקריפט שמריץ 24 שאלות שידוע מראש איפה התשובה שלהן. במאגר העברי, חיפוש וקטורי לבד מצא את הקטע הנכון ב-20 שאלות, ו-Hybrid רק ב-17. לכן כיביתי את BM25 (`USE_BM25 = False`). המנגנון נשאר בקוד, וכשאפעיל Reranker אוכל להדליק את BM25 שוב ולמדוד מחדש.

## הערה על מאגר הידע

המסמכים בתיקייה `skyshift_kb` מתארים את SkyShift, מיזם הדגמה. חלק מהפרטים בהם, כמו שמות המייסדים, ההיסטוריה ונתוני הרכבים, נכתבו לצורך הפרויקט, ואינם מתארים גוף אמיתי.
